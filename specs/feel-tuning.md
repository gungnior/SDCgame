## 0. 一句话结论

**开火前预警（A 方案）实测生效**：贴脸（2~3 格）的总反应时间从改造前的 **0.18~0.27 秒**
提到了 **0.38~0.45 秒**；并且**每一个距离都能靠一次闪避（1.5 身位）离开弹道** ——
这一点在探针里是**不给无敌帧**测的，也就是说最坏情况也成立。

## 3. 从实测得出的四条结论

1. **预警公式按设计工作**：2 格吃到上限 0.20 秒，3 格 0.177 秒，4 格起落到下限 0.12 秒；
   总反应时间**任何距离都不低于 0.38 秒**（改造前 2~3 格只有 0.18~0.27 秒）。
2. **侧闪在所有距离都成立**，且**不依赖无敌帧** —— 因为位移 1.35 格 > 弹道半宽 0.9 格，
   结构上就离开得掉。这是"1.5 倍身位"这个数值选得对的证据。
3. **无敌帧只在 ≤2.4 格才是必需的**（飞行时间 ≤ 0.22 秒时）；走廊里它仍是唯一解（见 `dodge.gd`）。
4. **AI 的交战带 5~9 格 → 0.58~0.85 秒反应窗口**，落在舒适区。

## 4. 多敌同时开火的量级 —— **B 方案已实施（2026-10-13）**

> 令牌桶：`SPAWN_RATE = 2.0` 条/秒、`SPAWN_BURST = 2.0`；
> 敌人开火前查配额，不足则**延迟**（不扣冷却、不计发数），不是打空。
> 调参口径：`SPAWN_RATE` 应与最大闪避频率（1.18 次/秒）同量级。

### 原问题记录（保留）

本轮只做了 A（预警）。**入射量问题依旧**：闪避最多 1.18 次/秒，
而多个敌人合计可以打出 6+ 条弹道/秒。三个拾荒者全中时 1.39 秒倒下。

| 方案 | 做法 | 代价 |
|---|---|---|
| B | **同时开火节流**：同一时间窗内最多允许 N 个敌人放弹道（与"每帧最多建 1 个流场"同一思路） | 削弱"人多势众"的压迫感 |
| C | 纯数据调节奏：`data/enemies.json` 的 `attack_cooldown` 调大 | 只拉长节奏，不解决近距公平 |

## 5. 调参对照表（真机上抱怨 → 拧哪个旋钮）

| 感受 | 旋钮 | 方向 |
|---|---|---|
| 弹道太快，来不及躲 | `LaneShot.DEFAULT_SPEED`（11） | 调小 → 飞行更长 |
| 预警太短，看到线就挨打 | `LaneShot.MIN_REACTION_SEC`（0.45） | 调大 → 贴脸预警更长 |
| 预警太久，像慢动作 | 同上 / `WARN_MAX`（0.20） | 调小 |
| 走廊里必中，很挫败 | `DodgeState.INVULN_SEC`（0.22） | 调大（如 0.28） |
| 闪避按不出来 | `DodgeState.COOLDOWN`（0.85） | 调小（如 0.6） |
| 闪避滑得太远 | `BodyMetrics.DODGE_DISTANCE` 的 1.5 倍 | 改 1.2 倍（仍 > 1 身位） |
| 自动作战太莽 | `PlayerAutopilot.STANDOFF_MIN/MAX`（3/8） | 一起调大 |
| 自动闪避抢手 | `AUTO_DODGE_LOOKAHEAD`（0.30） | 调小 |
| 十字键位按不着 | `CROSS_ARM_RATIO`（1.95）/ `CROSS_MARGIN_RATIO`（2.9） | 按机型微调 |

## 6. 上机清单（按顺序，每项记一句）

1. 左摇杆推着 + 点中心闪避 → 是否朝那个方向闪（任意角度）？
2. 找拾荒者对射：**红色瞄准线**是否一眼可辨、闪烁是否提示"快打出来了"？
3. 看到瞄准线再按闪避，成功率如何？再故意贴到 2~3 格试 —— 是否不再是"必中"？
4. 走廊 vs 开阔处各试两次（验证无敌帧与位移各自的必要性）。
5. 故意引 3 个敌人一起开火 —— 是否 1~2 秒就倒（对应第 4 节）？据此决定要不要 B 方案。
6. `G` 开自动作战：是否①绕墙走向容器 ②到点自动搜刮 ③锁最近的敌人 ④弹道来袭自动侧闪？
7. 十字键位的拇指舒适度（中心闪避是否顺手、四臂是否够得着）。
