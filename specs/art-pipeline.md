# 美术管线规格：2D 像素（方向裁剪方案）

# 🔴 2026-10-12 决策变更：**技术验证期用「极简白模」——但不要写死**

> **拥有者拍板**：目前不做像素风格，先按极简白模做技术验证。
>
> ⚠️⚠️ **但白模只是"现在用来技术验证"的临时渲染，不是最终美术方向 —— 不要写死，
> 必须给后来的真美术留好替换接口。**（拥有者 2026-10-12 补充）
> 换句话说：白模是**手段**不是**目的**；任何"白模永久化"的写法都是错的。
>
> ── 当前（技术验证期）──
> · 渲染：`RENDER_WHITEBOX` 为默认（`raid_scene.gd` 的 `render_mode`），F5 可切对比。
> · 语义（见 `view/whitebox_painter.gd`）：**亮 = 可走，暗 + 描边 = 阻挡**；
>   实用色板：地板 0.42 / 走廊 0.34 / 墙 0.07 / 墙描边 0.62 / 门 0.82 —— 对比度 3.8:1。
> · 白模↔碰撞一致性：`s09::_test_whitebox_matches_collision` 像素级保证
>   （"图上看起来是墙的格子，碰撞层也必须是墙"，真机反馈 #1 的修法）。
>
> ── ⭐ 给后来美术留的替换接口（**已存在，别绕过、别另起炉灶**）──
> 1. **渲染切换点**：`RaidMapBaker.build(grid, rooms, whitebox)` —— `whitebox=false`
>    即走美术资产路径（`_build_tiles` + `_bake_structure`）。**换渲染只动这一层**，
>    模拟层（`sim/`）完全不知情，这条边界必须保持。
> 2. **资产层**：`art/tiles/*.png`（16×16，可由 `tools/art/gen_tiles.py` 程序化生成）；
>    `RaidMapBaker.TILE_NAMES` 是"材质键 -> tile 文件名"的映射 —— **换美术只改这张表**。
> 3. **模式开关**：`raid_scene.RENDER_WHITEBOX` / `RENDER_ART`，便于随时对比调试。
> 4. **白模本身也保持可替换**：`WhiteboxPainter` 是纯函数 `paint(grid, rooms) -> Image`，
>    将来换掉它不影响别处（它只被 `RaidMapBaker._build_whitebox` 调用）。
>
> ── ❌ 不要做的事（防止把临时方案写死）──
> · 别新增"白模必须唯一 / 禁止替换"的约束或断言。
> · `s09::_test_whitebox_is_default` **是技术验证期的守卫**（防止手滑切走），
>   它**不是**"白模永久锁定"的承诺 —— 接真美术时由人决定是否一并调整，不要拿它挡需求。
> · 别在模拟层（`sim/`）里掺任何渲染/美术假设；模拟层对"白模还是美术"必须完全无感。
>
> 像素资产/工具保留不删（`gen_comfy` / `postprocess` / `gen_tiles` / `palette` / `art/gen`），
> 将来是重启像素风、还是改走别的风格，由拥有者在技术验证通过后决定。

> 本文件定义**所有美术资产的硬规格与生产流程**，是 AI 生成素材时的验收标准。
> 自包含。目标读者：项目拥有者 + 后续生成/处理素材的 Agent。
> ⚠️ 见上方变更：**当前不按本文件推进**，本文件为存档规格。
> 关联文件：`specs/feasibility.md`（可行性评估，决策 D-03 / D-04 / D-08 / D-09 / D-10 / D-11 / D-12 出自此处）、
> `specs/third-party.md`（第三方资源登记与署名清单）。

## 1. 方案总纲

### 1.1 核心决策

| ID | 决策 |
|---|---|
| **A-01** | **方向裁剪**：玩家 **4 方向**（正/背/侧，侧靠镜像 = 3 套唯一图）；普通敌人 **2 方向**（侧视 1 套 + 引擎镜像）；精英/Boss **4 方向** |
| **A-02** | **枪械与手臂独立旋转绘制**，**烘焙 12 个角度**（每 30°），不实时旋转 |
| **A-03** | 调色板**锁定 40 色**，所有素材生成后强制量化到该调色板 |
| **A-04** | 画布尺寸全项目固定，见 §2 |
| **A-05** | 上下移动**精灵只做位移**，靠枪械旋转 + 朝向指示器 + Y 轴步态抖动补足表现 |
| **A-06** | **外部素材必须经 `import_external.py` 统一化后才可入库**，风格锚定到唯一主基底包（Kenney） |
| **A-07** | **引入即登记**：任何外部素材落地前先写 `specs/third-party.md`，LICENSE 原文存档于 `art/_licenses/` |
| **A-08** | **禁止使用 CC-BY-NC-ND 与任何商业游戏提取素材**（ND 禁止修改，提取素材必然侵权） |

### 1.2 理由

`A-01` 使角色动画资产量从 ~756 帧降至 ~283 帧（**−63%**），并把 AI 最难做到的"跨 4 套方向的风格一致性"压缩到 1 套。
`A-02` 是 `A-01` 的**成立前提**：若枪只有左右朝向，敌人朝上朝下视觉完全相同，玩家无法判断威胁方向，游戏不可玩。

**业界先例**：Nuclear Throne、Hotline Miami、Brotato 等俯视射击均采用"身体仅左右朝向 + 枪械自由旋转"。

## 2. 硬规格

| 项 | 值 | 说明 |
|---|---|---|
| 基础 tile | **16 × 16 px** | 全项目唯一 tile 尺寸 |
| 角色帧画布 | **48 × 48 px** | 身体约 32×32，**其余留作枪械旋转余量** |
| 角色对齐 | 脚底中心锚点 `(24, 40)` | 所有帧必须对齐此锚点，否则会抖 |
| 物品图标 | **32 × 32 px** | 背包格子显示 |
| 枪械底图 | **48 × 24 px** | 侧视，枪口朝右；锚点在握把 |
| 配件图标 | **32 × 32 px** | 背包显示用 |
| UI 图标 | 16 × 16 与 24 × 24 | 两档 |
| 调色板 | **40 色锁定** | 见 §8.2 |
| 格式 | PNG-32（角色/VFX/UI）· PNG-8（tile / 图标） | 无 premultiplied alpha |
| 像素密度 | 全部为 1× 原生像素，**禁止缩放产出** | 整数倍缩放由引擎运行时处理 |

### 锚点定义（必须写进图集元数据）

| 锚点名 | 用途 |
|---|---|
| `foot` | 角色脚底中心（身体层） |
| `shoulder` | 肩部，手臂/枪械旋转中心 |
| `muzzle` | 枪口，用于生成火光/弹壳 |
| `hand_r` / `hand_l` | 双手持枪位置，用于手臂层对齐 |

## 3. 分层结构

每个角色/敌人由 **4 个独立图层**组成，引擎按顺序合成：

```
① 影子层     固定在地面，不随身体 Y 抖动
② 身体层     左/右 2 方向，引擎水平翻转（玩家/Boss 为 3 套唯一图）
③ 手臂+枪械层 绕 shoulder 锚点旋转，跟随瞄准角度（12 角度烘焙图）
④ 指示层     脚下朝向三角 / 警戒状态着色 / 视野锥
```

### 3.1 表现补偿（A-05 的落地，**不可省略**）

上下移动时精灵只平移，若不做补偿会呈现"滑冰感"。三项必做：

| 手段 | 实现 | 效果 |
|---|---|---|
| **Y 轴步态抖动** | 行走时身体层 Y 偏移 ±2 px，一步一次（与 walk 帧同步） | 最有效，成本几行代码 |
| **地面影子** | 影子层不参与抖动，锁在地面 | 立刻产生"站立感" |
| **脚步尘土/脚印 VFX** | 每 2 步撒一次粒子 | 补足位移反馈 |

### 3.2 朝向可视化（A-01 的必要补偿）

裁剪掉正/背视图后，"敌人背对我还是在看我"在视觉上不可分辨，而 AI 索敌 + 潜行是核心机制。**以下三件套必做**：

| 元素 | 说明 |
|---|---|
| 脚下朝向指示器 | 小三角/扇形，跟随枪械旋转角度 |
| 警戒状态着色 | 放松 = 灰白 / 警觉 = 黄 / 交战 = 红 |
| 敌人视野锥 | 玩家蹲伏时显示，可选 |

## 4. 动画帧表

### 4.1 基础帧组（Baseline Set）= 19 帧 / 套

| 动画 | 帧数 | 循环 | 备注 |
|---|---|---|---|
| `idle` | 2 | 是 | 呼吸起伏 |
| `walk` | 6 | 是 | 步态，配合 Y 抖动 |
| `shoot` | 2 | 否 | 后坐 |
| `reload` | 4 | 否 | 换弹 |
| `hit` | 1 | 否 | 受击闪白（可引擎实现） |
| `death` | 4 | 否 | 倒地 |

### 4.2 敌人精简帧组 = 14 帧 / 套

| 动画 | 帧数 |
|---|---|
| `idle` | 2 |
| `walk` | 6 |
| `shoot` | 2 |
| `hit` | 1 |
| `death` | 3 |

### 4.3 分配与总量

| 角色 | 唯一图套数 | 帧数 |
|---|---|---|
| 玩家 | 3（正 / 背 / 侧） | 3 × 19 = **57** |
| 普通敌人 × 8 | 1（侧视，镜像） | 8 × 14 = **112** |
| 精英 / Boss × 2 | 3 | 2 × 3 × 19 = **114** |
| **合计** | | **~283 帧** |

> 玩家方向上多给，是因为**只有 1 份**，加正/背视图成本极低而观感收益最大。
> 普通敌人有 8–10 份，翻倍就是翻 8 倍，用朝向指示器补偿即可。

### 4.4 可选扩展帧组（按需追加，不进 M1/M2）

| 动画 | 帧数 | 触发条件 |
|---|---|---|
| `run` | 6 | 冲刺机制确定后 |
| `crouch_idle` / `crouch_walk` | 2 + 4 | 潜行机制确定后 |

## 5. 枪械与配件

### 5.1 烘焙角度

- **12 个角度**（每 30°），覆盖 0–330°
- **AI 只画 1 张侧视图**（枪口朝右），其余 11 个角度由**脚本旋转烘焙**产出
- 烘焙必须用**最近邻 + 像素对齐**，产出后手工修掉明显锯齿（重点修枪管与瞄具）

```
art/guns/{gun_id}/base.png          ← AI 生成，1 张
art/guns/{gun_id}/rot_000.png ...  ← 脚本产出，12 张
```

> 资产文件数变多，但 **AI 生成次数每把枪只 +1**，成本极低。

### 5.2 配件（D-08）

第一版**只改数值，不做视觉变形**。配件仅需：

- 背包图标 32×32（120 个）
- 可选可见图层（弹匣 / 瞄具 / 枪口），每个带独立锚点，按锚点叠加到 `base.png` 上，约 30 张

**禁止**为每个配件绘制独立枪身，那是组合爆炸。

### 5.3 手臂层

1 套（不区分方向），跟随枪械旋转对齐 `hand_r` / `hand_l`。

## 6. 地图 / VFX / UI

### 6.1 Tile（~400 张）

| 类别 | 说明 |
|---|---|
| 地面 | 需支持 9 宫格或 47-blob 自动拼接 |
| 墙面 | 顶部带高度，侧面带阴影 |
| 门 / 可破坏物 | 含破损中间帧（3–4 帧） |
| 装饰 / 杂物 | 箱子、家具、尸体、车辆 |

**接缝处理**：AI 不擅长直接产出无缝 tileset。流程为 **AI 出单块 → 手工修边 → 脚本拼装校验**。

### 6.2 VFX（~60 组）

枪口火光、弹壳、血、烟雾、爆炸、弹孔、玻璃碎裂、火花。
每个 VFX ≤ 8 帧，尺寸 ≤ 64×64。

### 6.3 UI（~60 张）

按钮、面板边框、图标、准星、血条、状态图标（~40 个）。
**UI 是 AI 表现最好的部分，可放心批量生成。**

## 8. 生产工作流

### 8.1 单资产流程

```
① 写 prompt（基于 §2 硬规格 + §8.2 调色板约束）
② AI 生成候选（单帧，不要要求它出连续帧）
③ 量化到 40 色调色板
④ 对齐到规定画布尺寸与锚点
⑤ 手工修帧（修抖动、修锯齿、修锚点漂移）
⑥ 脚本补帧 / 旋转烘焙 / 图集打包
⑦ 真机预览，通过则入库
```

### 8.2 调色板策略

- 建立项目专属 **40 色**调色板文件（`.gpl` 或 `.pal`），放于 `art/palette.gpl`
- 所有 AI 生成素材**必须**经量化脚本处理后再入库
- 量化后用**抖动（dithering）** 补偿渐变带

### 8.3 关键工具（自建脚本，AI 生成的性价比极高）

| 脚本 | 作用 |
|---|---|
| `quantize.py` | 批量量化到项目调色板 |
| `align_anchor.py` | 校验/修正脚底锚点对齐，检测帧间漂移 |
| `bake_rotations.py` | 枪械 12 角度烘焙 |
| `pack_atlas.py` | 图集打包 + 生成锚点元数据 |
| `validate_assets.py` | 校验尺寸/命名/调色板合规，输出违规清单 |
| `preview_sheet.py` | 生成 GIF/精灵表供快速目视检查 |
| **`import_external.py`** | **外部素材导入适配（见 §8.5）** |
| **`audit_licenses.py`** | **扫描 `specs/third-party.md` + `art/_licenses/`，检测授权冲突与 ND 素材** |
| **`gen_credits.py`** | **从登记表自动生成 `CREDITS.md`（禁止手工维护）** |

### 8.4 动画帧一致性策略（AI 的弱项，必须绕开）

**不要**让 AI 一次生成"6 帧走路动画"——角色会在帧间变形、脚数不对、配色漂移。

**正确做法**：
1. AI 只生成 **idle 关键帧**（1 帧）
2. 用 **Aseprite Lua 脚本**或自建脚本，做程序化的**肢体位移/摆臂/上下起伏**，产出 walk / shoot / reload
3. 手工修关键帧（约 30% 的工作量集中在死亡与换弹两个动作）
4. 用 `preview_sheet.py` 出 GIF 目视验收

### 8.5 外部素材导入流程（D-10）

外部素材（Kenney / itch.io CC0 / OpenGameArt / Freesound）**不能直接放进项目**，必须经统一化处理。

```
① 选源     优先 CC0（零义务），其次 CC-BY / CC-BY-SA / CC-BY-NC
② 登记     立即写入 specs/third-party.md（来源/授权/URL/用途）
③ 存档     把该素材的 LICENSE 原文存入 art/_licenses/{source}/
④ 适配     import_external.py：量化调色板 → 重设锚点 → 裁剪方向数 → 重排帧序 → 重命名
⑤ 校验     validate_assets.py + 目视比对主素材包风格
⑥ 入库     过 §9 全部验收项
```

**`import_external.py` 必须处理的 5 件事**（这是 D-10 的隐藏成本）：

| 处理项 | 说明 |
|---|---|
| 调色板量化 | 强制映射到项目 40 色，必要时加抖动 |
| 尺寸归一 | 缩放到 §2 规定画布（**只允许整数倍或最近邻**，禁止双线性） |
| 锚点重设 | 重算 `foot` / `shoulder` / `muzzle` 锚点 |
| 方向裁剪 | 4/8 方向素材 → 裁剪到 D-03 规定的 2 或 4 方向 |
| 帧序重排 | 不同素材包的帧播放顺序不同，需显式映射 |

### 8.6 风格锚定规则（防止拼盘）

**这是 D-10 引入的最大风险，必须用制度压住：**

1. **选定唯一主基底包**（推荐 [Kenney **Desert Shooter Pack**](https://kenney.nl/assets/desert-shooter-pack)，**CC0**，16×16 像素画，shooter/roguelike 题材）——**不要用 `Top-down Shooter`，那个是矢量风格**
2. **其余来源只允许补主包没有的缺口**，不允许同类替换
3. 每个外部素材入库时，必须与主包同色板、同描边粗细、同光源方向
4. **光源方向全项目统一**（建议左上），阴影方向不得例外
5. 每入库 10 个外部素材，出一次并排对比图人工检查

> 判据很简单：**把新素材和主包素材并排放在一张图里，如果你能一眼看出哪个是外来的，就还没过。**

## 9. 验收标准（逐项勾选）

- [ ] 画布尺寸与 §2 完全一致，无 1px 偏差
- [ ] 锚点对齐，连续帧间 `foot` 锚点漂移 ≤ 1 px
- [ ] 颜色数量 ≤ 40，且全部来自 `art/palette.gpl`
- [ ] 无抗锯齿残留（无半透明边缘像素）
- [ ] 命名符合 §7 规范
- [ ] 角色在 4 方向移动 + 各角度瞄准下的真机预览无穿帮
- [ ] 枪械 12 角度烘焙无可见锯齿（重点检查枪管）
- [ ] tile 自动拼接无接缝
- [ ] 与既有素材并排目视，风格一致（色温 / 描边 / 阴影方向统一）
- [ ] 真机 60 fps 下无闪烁、无像素抖动
- [ ] **外部素材已登记到 `specs/third-party.md`，LICENSE 原文已存入 `art/_licenses/`**
- [ ] **与主基底包并排目视，无法分辨哪些是外来素材**

## 10. 预算摘要

| 项 | 数值 |
|---|---|
| 角色动画帧总数（AI 生成） | ~283 帧 |
| **AI 图像生成调用次数**（D-10 后） | **3,000 – 4,000 次** |
| 图像生成现金成本 | $80 – $250 |
| 外部素材采购成本 | **$0** |
| 美术侧 token | 2 – 3 M（**外部素材适配脚本会使其小幅回升**） |
| 相比 4 方向全量方案节省 | 资产 −63% |
| 相比纯 AI 方案（D-10 收益） | 生成次数 −25%，**通用件观感明显提升** |
| D-10 新增成本 | `import_external.py` 等适配脚本开发（**须计入工作量，不是免费午餐**） |

> 保守起见，**每张 AI 成品按 4 次生成 + 1 次重做预算**。若某类资产返工率超过 6 次/张，停下来检查 prompt 模板而不是继续加次数——通常是规格描述不清导致的系统性偏差。

## 11. 授权与署名（D-09 / D-12）

本项目为**非商用 + 免费发布 + 开源（MIT，2026-10-13 拍板，原 GPL-3.0）**，可用素材范围见 `feasibility.md` §3.1。

### 11.1 按授权类型的义务

| 授权 | 义务 |
|---|---|
| **CC0 / Unlicense / MIT** | 无义务。**仍建议登记**（便于追溯来源） |
| **CC-BY** | **必须署名**（作者 + 作品名 + 链接 + 授权名） |
| **CC-BY-SA** | 署名 + **衍生素材同协议开源**（注意：会传染你改过的素材，但不传染代码） |
| **CC-BY-NC / NC-SA** | 署名 + 禁止商用（本项目符合） |
| **CC-BY-NC-ND** | 🚫 **禁止使用**——游戏必然要修改素材（缩放、调色板、裁剪） |
| **GPL 系列** | 项目整体以 MIT 发布；GPL-3.0 素材可并入（其自身仍按 GPL 条款），GPL-2.0-only 禁用（R-06） |

### 11.2 强制纪律

1. **引入即登记**——素材落地前先写 `specs/third-party.md`，不允许"先用了再说"
2. **LICENSE 原文必须留档**——存于 `art/_licenses/{source}/`，防止上游删库后无法举证
3. **`CREDITS.md` 由 `gen_credits.py` 自动生成**，禁止手工维护（手工必然漏）
4. **`audit_licenses.py` 纳入提交前检查**——发现 ND 素材或授权冲突立即报错
5. **署名要出现在玩家能看到的地方**——游戏内 Credits 界面 + 仓库 `CREDITS.md`。CC-BY 的署名义务**不因"游戏是免费的"而免除**

### 11.3 优先顺序

```
CC0  >  CC-BY  >  CC-BY-SA  >  CC-BY-NC
（零义务）        （会传染）    （限制最多）
```

**首选 Kenney 全套（CC0）**：零义务、风格统一、覆盖广，能一次性解决大部分通用件。
