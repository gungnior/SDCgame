**我之前的验收是弱的。** 我只用「性感女性」跑了 10 次全部干净，就宣称修好了。

### 1.2 根因判断（我的分析，你可以推翻）

**固定约束块确实在上下文里**（已用日志确认注入：`00-quick-start.md`、`03-self-check.md`、`13-detail-mood.md`）。
所以这**不是**「规则没进上下文」的漏检，而是**指令冲突**：

> 用户明确要求「月光」「霓虹」「逆光」→ 模型**优先服从用户**，而不是优先服从禁令。

这是比上一轮更难的一类问题。**光靠"把规则塞进上下文"解决不了。**

### 1.3 候选方向（选一个或组合，你自己判断）

**A. 措辞强化（主路径，改技能文件）**
`SKILL.md` 与 `13-detail-mood.md §13.6` 目前只写「禁止输出光线/光影/色调标签」。
需要补上**冲突时的处置规则**，例如：

> 当用户明确要求光线/光影/色调（如"月光下""霓虹灯""逆光"）时，
> **用环境、时辰、天气、氛围标签表达该意图，绝不输出光线类标签**。
> 例：「月光下的沙滩」→ `night, beach, starry sky, ocean, wet sand, tranquil`

关键是给出**替代写法示例**，而不只是"禁止"。

**B. 服务端确定性后处理（兜底，最可靠）**
输出后扫描禁止清单，命中就：剔除该标签 / 重新生成 / 追加一次修正调用。
这条路**不依赖模型的服从性**，但需要你判断误伤风险（例如 `lit` 会命中 `split`）。

**C. 禁令位置前移**
把禁令放进 `SKILL.md` **最顶部**（现在在 `§2` 和 `§13.6`）。每轮必注入，位置最靠前。

**D. 两段式自检**
生成后再用一次便宜的模型调用做「禁令自检并修正」。成本是多一次往返。

**我的倾向：A 为主 + B 兜底。** 但你实测后可以推翻，只要给出理由和数据。

### ⚠️ 三个已知陷阱（我都踩过，别再踩）

1. **启动 Electron 应用前清掉 `ELECTRON_RUN_AS_NODE`**：
   ```powershell
   Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
   ```
   不清的话 Chatbox 会被当成纯 Node 执行，**立刻退出、无窗口、无日志、退出码 0**。
   我在这上面浪费了三轮。

2. **Chatbox 安卓的 UI 是整个 WebView**，`uiautomator` 看不到内部控件，只能**截图估坐标**。
   读回复原文请直接拉数据库：
   `/data/data/xyz.chatboxapp.chatbox/databases/chatboxSQLite.db` 的 `key_value` 表，
   session 内容在 `contentParts[].text`（`content` 字段是空串，**`??` 不会穿透，要用 `||`**）。
   参考 `chatbox-last-reply.mjs`。

3. **PowerShell 里别用内联 `node -e`** —— 引号会被吃掉。写成 `.mjs` 文件再跑。
   另外 PowerShell 变量名**大小写不敏感**，`$h` 和 `$H` 是同一个变量（我被这个坑过一轮）。
