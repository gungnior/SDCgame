## 二、性能优化：AI 单帧 257ms → 20ms

三轮定位，每一轮都靠**逐阶段埋点**精确到函数，不靠猜。

| 轮次 | 阶段峰值 | 根因 | 修法 |
|---|---|---|---|
| 起点 | **257.78 ms** | `Perception.hearing_cost()` 是**全网格 Dijkstra 且每次重新分配数组**，而它被**每个敌人 × 每个噪声 × 每帧**调用 | 新增 `hearing_field()` 一次覆盖全图 + `HearingFieldCache`；**按"噪声"建场而不是按"敌人"**（噪声每帧 1~3 个且固定，敌人 20+ 个且一直动）→ **8 倍** |
| 第二轮 | **32.02 ms**（`ai_act`） | `FlowFieldManager.field_for()` 缓存未命中就立刻建整个流场，**没有每帧预算**。玩家一动，多个敌人同帧各自建场 | `MAX_BUILDS_PER_FRAME = 1`，超出的本帧复用旧场 |
| 第三轮 | 视觉确认 FPS 120 / 平均 8.3ms（PC） | 枪口火光粒子与 `_draw()` 多边形**重复**；`CPUParticles2D.restart()` 在移动端很贵 | 移除重复粒子 |

**真机累计效果**：尖峰从 **115 次**降到 **6 次**；存活时间从 **3.3 秒**（开局即死）到**能完整打完一局并撤离**。

## 三、发现并修复的缺陷清单

### 3.1 崩溃 / 卡死级

| 症状 | 根因 | 修法 |
|---|---|---|
| 按 ESC **卡死** | `get_tree().paused` **同时门控"逻辑推进"和"节点能否收输入"**。只把菜单自己设成 `ALWAYS` 不够，子按钮仍 `INHERIT` → 菜单看得见、点不动 | **弃用 `get_tree().paused`**，改纯逻辑冻结（`Game.paused` + 场景 `_process` 跳过游戏逻辑）。输入路径完全不变 → 不可能再点不动 |
| 按 ESC **看不到「继续」** | `Control` 直接挂 `CanvasLayer` 下时 `set_anchors_preset(FULL_RECT)` **解析不到父矩形** → 自身 `size=(0,0)` → 子树全塌、`ScrollContainer` 裁掉内容 | `_fit_viewport()` 钉住视口 + 监听 `size_changed`；操作按钮移到**顶部固定栏** |
| 藏身处看不到「出发」 | 同上 + 内容总高 586px > 视口 360px，按钮在滚动区末尾 | 同上；「开始下一局」放顶部固定栏 |

### 3.2 逻辑错误

| 症状 | 根因 | 修法 |
|---|---|---|
| **枪声随机消失**（`音频掉 95`） | 并发计数只数 `_live` 里的名字，而 `_live` 条目**播完后从不清理** → 步枪响过 `max_simul` 次后**永远被丢弃** | 计数必须**同时**满足「槽位登记的是本人」**且**「它现在真的在播」 |
| **贴脸打不中** | 只用 4.2° 角度锥；1 格外偏 0.3 格 = 17°，永远打不中。偏折上限也只限角度（6°） | 加实体半径 hitbox（0.45 格）；偏折上限改按**横向距离**（0.55 格 → 近距离可偏 33°、远距离仅 3°） |
| **子弹从敌人身上穿过去** | `pick()` 已判定命中后又**掷了第二次随机数**；桌面 `_aim_push()` 返回 0，而 `pick` 在 `push < 0.22` 时直接返回空 | 去掉双重判定（`pick` 找到即命中）；散布改为**收缩有效 hitbox**；桌面给恒定推力 |
| **自动射击对墙开火** | 开火用 `has_lock`，而它含 **1.2 秒锁定粘性** → 敌人躲墙后仍朝墙打满 1.2 秒 | `update()` 区分 `has_lock`（平滑瞄准）与 `visible`（当前真有视线）；**开火要求 `visible`** |
| **敌人顶墙 / "能走却走不了"** | **我自己引入的**：流场预算用尽返回 `null`，调用方退化成"朝目标直走"——**直走无视墙** | 预算用尽返回 `_last_field`（旧场**仍然绕墙**）；真不可达时探测前方一格，不可走则**沿墙滑动** |
| **火花全堆在地图左上角** | `fx.burst()` 收到**逻辑格坐标**（5.5），粒子在世界空间 **1 格 = 48 像素** | `FxPool.burst()` 内部统一 `pos * CELL_PX`；调用方一律传逻辑格坐标 |
| 治疗按钮"没反应" | 按钮是好的，**背包是空的**（`_setup_sim` 从没发过物品）；失败只 `push_warning`，手机上不可见 | 起始配装 + HUD toast 反馈 |
| 结算「回藏身处」回到原地 | 错误地接到了 `_restart` | 接 `_go_hideout()`，真正切场景 |
| 绿线像墙、实际能走 | 房间描边画在 `room.rect` 最外圈**瓦片**上，而 `room.rect` 整块都是 carve 出来的地板 | 描边只画在"朝房间外"的墙格一侧 |

### 3.3 度量 / 观测错误（最隐蔽的一类）

| 症状 | 根因 |
|---|---|
| 报出 **1787 次 80ms 卡顿**，而同窗 `avg_ms = 16.13ms`（正好 60fps）——**自相矛盾** | `Performance.TIME_PROCESS` **在 Android 上不可靠**。改用 `Time.get_ticks_usec()` 墙钟 |
| HUD 显示 `FPS 60  帧 25.2 ms` —— 同样矛盾 | **同一个坑踩两次**：遥测改了，**HUD 那一路漏改** |
| 出现 `draw_end = 4917 ms` 的"5 秒冻结" | `Tel` 阶段计时器**跨场景没重置**，新场景第一次 `mark()` 算的是**上个场景最后一次 mark** 以来的间隔（实际只是在藏身处待了 4.7 秒）。新增 `reset_phases()` |
| 卡顿帧全报 `ctx=draw_body`，但 `age` 只有 2~3ms | 只记"最后一个标记"会误导。改成**逐阶段计时**，并区分 `draw_body`（搬指令 2ms）与 `draw_end`（渲染 + vsync） |

## 四、方法论沉淀（本会话最有价值的部分）

### 4.1 真机遥测直连 —— 不再靠口述

游戏侧 `print("DSHTEL|{json}")` → logcat → 主机 `tools/monitor_game.py` 实时解析。
**走 USB 调试通道，不需要 INTERNET 权限**，与"零网络"约束不冲突。

踩过的坑：
- vivo ROM 会**过滤未知 tag 的 INFO 日志**，必须显式 `logcat godot:V *:S`
- **必须用实时流，不能用 `logcat -d`** —— 2MiB 环形缓冲区几秒就被其他应用冲掉

### 4.2 布局探针 —— UI "看不见"先跑它，不读代码猜

`test/menu_probe.tscn` / `test/hideout_probe.tscn`：
递归枚举所有带文字的控件，报告 `global_position` / `size` / **是否在视口内**，并存截图。
（必须用**场景**当主场景跑；`--script` 模式下 autoload 不注册。）

**这一轮直接抓出两个 bug**：设置菜单塌成 0 尺寸、藏身处按钮被挤出屏幕。

### 4.3 截图优先于推测

"火花在左上角"、"看不到继续"、"视野锥透视" —— 每一个都是**先看到图**才定准的。

### 4.4 测试既是防线也是探针

本会话测试**多次纠正了我自己的错误判断**：
- 我以为代价函数天然对称 → 测试打脸（57 vs 51）→ 发现"按进入格计费"不对称
- 我以为偏折权重无所谓 → 测试发现权重塌到 0.08 → "判定命中但曳光飞向别处"
- "同一帧只建 1 个流场"断言数**"返回非空"**而非**构建次数** → **错了两次**

## 五、我犯的错误（诚实记录）

1. **`Control` 尺寸塌成 0 —— 同一个根因踩了三次**（虚拟摇杆 / 结算面板 / 设置菜单），每次都当孤立 bug 修。第三次才做成通用修法 + 回归测试。
2. **`get_tree().paused` 修了两轮**（先设自己 ALWAYS → 再递归设子树 ALWAYS），两轮都是在给机制打补丁。**该在第一步就换掉它。**
3. **同一个度量错误踩两次**（遥测修了、HUD 漏改）。
4. **同一个测试断言错误踩两次**（数"返回非空"而非"构建次数"）。
5. **"新增字段忘了在转换函数里带上" 三次**（`treat` / `_load_attachments` / `aim_cone_deg`）。
6. **补丁脚本用「附近有尸体」当"已应用"标记**，而那句话也出现在别处注释里 → 补丁被**静默跳过**，我还以为成功了。**marker 必须唯一。**
7. **为压性能引入的优化，把行为降级了**（流场预算 → 敌人顶墙、无视墙的直走回退）。**优化必须验证行为等价，不只是看帧数。**
