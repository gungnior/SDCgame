## 七、本轮会话的增量（相对上一份会话报告）

### 7.1 性能：AI 单帧 **257ms → 20ms**

| 轮次 | 峰值 | 根因 |
|---|---|---|
| 起点 | **257.78 ms** | `hearing_cost()` 全网格 Dijkstra + 每次重分配数组，被**每敌人×每噪声×每帧**调用 |
| 二轮 | **32.02 ms** | `field_for()` 缓存未命中立刻建全流场，**无每帧预算** |
| 三轮 | — | 枪口粒子与 `_draw` 多边形**重复** |

**真机累计**：尖峰 **115 → 6** 次；存活 **3.3 秒 → 能完整打完一局并撤离**。

### 7.2 修复的缺陷（按性质）

- **卡死级**：ESC 卡死（`get_tree().paused` 连输入一起门控）· 看不到「继续」（Control 尺寸塌成 0，**同一根因第 3 次**）
- **逻辑错误**：枪声永久消失（`_live` 不清理）· 贴脸打不中（只有角度锥）· 子弹穿身（双重随机判定）· 自动射击打墙（锁定粘性）· **敌人顶墙（我自己引入的）** · 火花堆左上角（格/像素单位没对齐）· 治疗没反应（背包是空的）· 回藏身处回到原地
- **度量错误**：`Performance.TIME_PROCESS` 安卓上不可靠（**同一个坑踩两次**：遥测改了、HUD 漏改）· 4917ms 幽灵卡顿（跨场景计时器没重置）

### 7.3 方法论沉淀

1. **真机遥测直连** —— USB 通道，不违反零联网；不用口述
2. **布局探针** —— UI "看不见"先跑它，**这轮直接抓出 2 个 bug**
3. **截图优先于推测**
4. **测试既是防线也是探针** —— 多次纠正我自己的错误判断

## 十一、结论

1. **架构没有走弯路** —— 五条硬约束（模块按 C 划 / schema 定死 / API 定死 / 不写临时代码 / 数据开关）执行到位，这是 B→A 不需要重写的保证。
2. **门 1 的两个真实缺口是"内容"不是"系统"** —— 掉落痛感 + 难度平衡。按 roadmap §5 的原话：**回去改数值与节奏，而不是加系统。**
3. **M0 只剩存档**，这是唯一挡在 A 前面的技术项（也是"杀进程即丢进度"的根因）。
4. **本轮的真机联调能力（遥测 + 探针 + 截图）是最大的一次方法论升级** —— 它把"猜问题"变成了"看数据"，本轮 90% 的 bug 是这样定准的。
