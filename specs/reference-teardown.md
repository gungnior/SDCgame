> **用途**：把参考作品当**规格书**用，而不是素材库。拆出的**数值与规则不受版权保护**，可以放心用于本项目。

## 0. 合法边界（务必先读）

| 可以做 ✅ | 不可以做 🚫 |
|---|---|
| 记录数值（TTK、地图尺寸、掉落率、经济曲线） | 提取游戏素材（贴图、音频、模型） |
| 记录机制与系统结构 | 复制源代码 / 反编译产物 |
| 抄类型范式与 UI 布局思路 | **像素级复刻 UI 与角色形象** |
| 写"受 XX 启发"的说明 | 使用其名称 / 宣称官方关联 |

**方法论**：玩法规则不受版权保护（idea–expression 二分法），但**具体表达**（美术、代码、文本）受保护。
本文件的全部内容都属于"规则"范畴，是行业标准的 competitive analysis。

> ⚠️ 录屏仅作个人分析用。**不要把录屏、截图提交进公开仓库**——那是未授权素材的再分发。

## 1. 拆解方法

1. **固定版本号**——每次拆解先记录参考作品的版本（游戏更新会改数值，不记版本的数据是废数据）
2. **统一条件**——同一难度、同一角色配置、同一地图类型，否则数据不可比
3. **多次采样**——每个观测项至少 3 次，记录区间而不是单值
4. **录屏**——便于事后逐帧数 TTK 和 AI 反应延迟
5. **随手记感受**——"这里紧张""这里无聊"比数字更值钱，单开一节记

**推荐工具**：录屏 → 逐帧看（AI 反应延迟、枪口抖动）；秒表（换弹、治疗耗时）。

> **"无聊点"比"亮点"更有价值。** 参考作品里让你走神、想快点结束的部分，就是你本项目要砍掉或改掉的部分。

## 12. 拆解结论 → 落地动作

每完成一轮拆解，输出三样东西：

1. **数值表** → 直接写进 `data/*.json` 作为初始值
2. **要避免的坑** → 写进 `feasibility.md` §12 风险登记册
3. **新发现的机制** → 评估是否纳入，纳入则需在 `feasibility.md` §2 新增决策记录

> ⚠️ **不要照搬数值就完事**。你的美术观感、触屏操作、AI 行为都与参考作品不同，
> 照搬的数值必须经过自己的试玩调整。**参考值是起点，不是终点。**
